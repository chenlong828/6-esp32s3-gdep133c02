# EDPHost —— 电子纸传图（macOS / Swift）

配套固件 `firmware/epd_server` 的上位机：启动后在局域网里广播找设备，选中一张照片，
转成 1200×1600 六色抖动图，编译成 EPD6BIN，HTTP 传给 ESP32。

SwiftUI 写法，SwiftPM 包；`swift build` 即可编译，`./build_app.sh` 打成可双击的 `.app`。

---

## 1. 界面

```
┌ 工具栏：●已连接   [设备 ▾]   [重新扫描] ─────────────────────────────┐
├───────────────────────────────────┬──────────────────────────────────┤
│ [裁切 | 成品]  裁切框 4:3 · …       │ ① 设备：IP/MAC/固件/SD/当前图      │
│ ┌───────────────────────────────┐ │        手动 IP、刷新、归档、清屏    │
│ │  原图（保持拍摄方向）          │ │ ② 照片：选择 / 拖入                │
│ │  ┌─────────────────────────┐  │ │ ③ 画面：旋转/适配/抖动/强度        │
│ │  │ 半透明裁切框 3:4 / 4:3  │  │ │ ④ 生成并上传                       │
│ │  │ 拖框移动 · 拖四角缩放    │  │ │    [ 一键生成并上传 ]  ⌘↩          │
│ │  └─────────────────────────┘  │ │    仅转换预览 / 仅编译 / 导出      │
│ └───────────────────────────────┘ │                                    │
│  ── 六色占比 ──                    │ 运行日志                            │
└───────────────────────────────────┴──────────────────────────────────┘
```

- 启动即自动广播（UDP 3232），之后每 10 s 刷新一次设备列表。
- 广播被网络策略拦住时，可以手动填 IP 添加设备。
- 选中设备后每 3 s 拉一次 `/api/v1/status`，能看到 `刷新中 / 累计次数 / 当前图`。
- 图片可以直接从 Finder 拖到左侧预览区。
- 「查看归档」里能看设备 SD 卡上的历史图，并一键「重新显示」。
- 左侧有「裁切 / 成品」两个视图：裁切里调构图，成品里看真正会刷上屏的 6 色画面。

## 2. 构建

```bash
cd host/EDPHost

# 只编译（命令行验证）
swift build -c release --disable-sandbox

# 打成 .app（推荐）
./build_app.sh release          # 产物 host/EDPHost/build/EDPHost.app
./build_app.sh release run      # 打包后直接打开
```

> `--disable-sandbox` 是 SwiftPM 自己的构建沙箱。在某些受限环境（包括本仓库的
> agent 沙箱）里嵌套 sandbox 会失败，所以脚本里默认带上；正常桌面环境去掉也能编。

也可以用 Xcode 打开：`open Package.swift`（SwiftPM 包，Xcode 26 可直接跑）。

**首次启动**会弹「允许 EDPHost 访问本地网络吗？」——必须允许，否则广播发现和
HTTP 上传都会被系统拦截（`Info.plist` 里已写好 `NSLocalNetworkUsageDescription`）。

`.app` 是本地 ad-hoc 签名，没有公证；只在本机用，不要外发。

## 3. 裁切与旋转

顺序是 **先裁切、后旋转**：编辑器里始终显示图片本来的方向，方便构图；旋转只影响上屏方向。

| 旋转 | 裁切框比例 | 说明 |
|---|---|---|
| 0° / 180° | **3:4**（= 面板 1200×1600） | 竖构图直接上屏 |
| 90° / 270° | **4:3**（= 面板转过 90°） | 横构图；这块区域转到面板上正好又是 3:4 |

| 情况 | 怎么做 |
|---|---|
| 图片本身就是 3:4 | 裁切框正好铺满，可以直接转换 |
| 竖图但不是 3:4 | 拖四角等比缩放、拖框内移动，选要保留的区域 |
| 横图（4:3、16:9…） | 点「旋转 90°」→ 图保持原方向，裁切框变成 **4:3**，按横构图选区域；上屏时会顺时针转 90° |
| 只想整图放进去 | 「适配」选「完整留白」，裁切框消失，整图加白边 |
| 整图铺满但允许变形 | 「适配」选「拉伸」，不裁切 |

交互细节：

- 框外压暗（半透明黑），框内有三分线；
- 拖框内部移动，拖四个角**等比缩放**（对角固定）；
- 框被限制在图片范围内，最小约 4%；
- 改旋转后裁切框会在 3:4 / 4:3 之间切换并重置为居中最大；
- 「重置裁切」回到居中最大，效果等价于原来的 cover；
- **EXIF 方向会自动归正**（手机竖拍照片不会横躺着进来）。

裁切用归一化坐标（相对**未旋转**的源图 0…1）；转换时先按这个框裁切，再把框映射到
旋转后的坐标系、缩放到 1200×1600。所以**编辑器里看到什么构图，满分辨率转换就是什么构图**，
与缩略图尺寸无关。

## 4. 使用流程

1. 打开 App，等工具栏变成「已连接」（或手动输入设备 IP）。
2. 点「选择照片…」（⌘O）或把图片拖进左侧，自动进入「裁切」视图。
3. 调「旋转 / 适配」，拖裁切框选构图；再调抖动/强度。改完会自动重新转换。
4. 点「转换并预览」切到「成品」，确认 6 色效果和六色占比。
5. 点「编译成二进制显示格式」→ 得到 960 018 B（18 B 头 + 960 000 B 帧）。
6. 点「**一键生成并上传**」（⌘↩）→ 自动转换 → 编译 → 上传；设备先落盘归档再刷屏（实测刷新约 30 s）。

转换和上传是分开的两步，和需求里的「先转换 → 再编译 → 再传给 ESP32」一致；
编译后的字节数和 CRC32 会显示在卡片里，方便和 Python 工具/dump 对照。

## 5. 转换管线

和 `host/e6_convert.py`（官网在线工具逆向版）完全同构：

| 步骤 | 实现 |
|---|---|
| 解码 | ImageIO（JPEG / PNG / HEIC / TIFF 都能读），按 EXIF 方向自动转正 |
| 旋转 | 顺时针 0/90/180/270，90° 的倍数不重采样 |
| 裁切 | 归一化裁切框（相对旋转后的图），固定 3:4；不裁时居中最大 |
| 适配 | `cover` 在裁切框内铺满（默认）/ `contain` 完整留白 / `stretch` 直接拉伸（后两者不裁切） |
| 缩放 | CoreGraphics `.high` 插值，画进 1200×1600 sRGB 位图 |
| 抖动 | 对**面板实测色**（白/黑/红 160,32,32/黄 240,224,80/蓝 80,128,184/绿 96,128,80）做 FS 蛇形误差扩散；另有 fs / atkinson / stucki / jjn / none |
| 打包 | `白1 黑0 黄2 红3 蓝5 绿6`，高 nibble 在左，960 000 B |
| 容器 | `"EPD6BIN\0" + u16 w + u16 h + u16 frames + u32 interval + 帧数据`（小端） |

**逐字节对齐验证**：`tools/verify_swift_dither.py` 把同一份裸 RGB 分别喂给
Swift 和 Python，比较抖动+打包后的字节：

```
模式        强度    字节数       结果
fs-ser    1.0   960000    一致
fs        1.0   960000    一致
atkinson  1.0   960000    一致
none      1.0   960000    一致
fs-ser    0.5   960000    一致
CRC32            1000003   一致      py=467d498d swift=467d498d
```

缩放用的是 CoreGraphics，和 PIL 的 LANCZOS 不是同一套重采样，所以**整图**对比
会有约 0.2%~0.4% 的像素在抖动噪声上不同；把两边都做 8×8 盒式模糊后再比，
平均绝对误差只有 0.8~1.3/255 —— 视觉上不可区分。要严格复现 Python 的字节，
就直接用 `host/e6_convert.py` 出图。

## 6. 命令行模式

同一个二进制带参数运行就是无界面工具（方便脚本和验证）：

```bash
BIN=host/EDPHost/.build/release/EDPHost

# 完整转换：输出 EPD6BIN
$BIN --convert photo.jpg out/photo.bin --fit cover --rotate 90 --dither fs-ser

# 指定归一化裁切框（相对旋转后的图，x,y,w,h ∈ 0…1）
$BIN --convert photo.jpg out/photo.bin --crop 0.1,0.05,0.6,0.8

# 只出帧数据（不要 18 B 头）
$BIN --convert photo.jpg out/frame.bin --frame-only

# 裸 RGB888 → 抖动 → 打包（给逐字节验证用）
$BIN --dither-raw 1200 1600 in.rgb out.bin fs-ser 1.0

# CRC32
$BIN --crc32 out/photo.bin

# 对真机 / mock 跑一遍完整 HTTP 流程
$BIN --api-selftest http://192.168.1.50

# 无界面跑一遍「一键生成并上传」（按钮背后的同一条路径，真机联调用）
$BIN --oneclick-selftest photo.jpg 192.168.1.50

# 不开窗口，把裁切编辑器渲染成 PNG（改 UI 后快速看效果）
$BIN --render-crop photo.jpg crop.png 560 620
```

`--api-selftest` 会依次调用 status → 上传一张纯白帧 → history → display → clear，
任何一步 JSON 解析失败都会打印原因；没有板子时先用
`tools/mock_epd_server.py` 起一个假设备。

## 8. 已知限制

- 只支持 macOS 13+，UI 没做本地化（中文硬编码）。
- 没有 App 图标之外的资源、没有公证；ad-hoc 签名。
- 广播发现依赖“上位机与设备在同一广播域”；跨网段请手动填 IP。
- 转换是单线程 CPU 计算（1200×1600 约 0.2~0.7 s），切换参数/拖完裁切框会自动重算，没有取消按钮。
- 裁切框只有 3:4 一种比例（跟面板走），不支持自由比例或任意角度旋转。
- 上传是整包 POST，没有断点续传；960 KB 在 2.4 GHz 上预计几秒级（真机未实测）。
